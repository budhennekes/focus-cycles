## P0: trustworthy records and claims are MVP blockers

**1. A completed timer is not a productive outcome.** Skip sets `endsAt` to now and invokes the same completion path as expiry, which unconditionally sets `cycle.completed = true` (`index.html:3025–3047,3089–3095`). A near-zero skipped cycle can count toward a streak, a best window, and celebratory copy. Stop saves elapsed minutes with `completed = false`, but daily totals, session-row totals, and main history statistics exclude those minutes (`index.html:2480–2487,3101–3107,3229–3257,3423–3428`). Work ending early can still produce a useful outcome; finishing a timer can produce none.

Propose separate future fields for end reason (expired / ended early / stopped / recovered uncertain) and explicit target outcome (yes / partial / no / missing). Count trustworthy recorded timer minutes from both finished and interrupted records; call them **Recorded timer time**, never measured productive time. Preserve original legacy values. Existing data cannot reliably distinguish Skip from expiry, reconstruct pause intervals, or establish attention. Label legacy completion as “Timer marked complete”; do not silently reinterpret it as success or failure.

**2. Recovery can freeze the timer and inflate time.** A restored paused timer returns without `startRunner()`; the Resume click handler also does not start it (`index.html:3068–3087,4311–4319`). Thus the normal resumed interval is absent after reload; focus/visibility reconciliation is not a replacement. Snapshots omit `pausedAccumMs` and `pauseStartedAt` (`index.html:4255–4265`). Expiry calculates minutes using observation time rather than the deadline, so a delayed wake/reopen can count time beyond the intended block (`index.html:3036–3038,4322–4328`). Closing a window on macOS destroys its renderer while the process can remain alive; the main process does not run the timer (`main.js:176–177,280–288`). Test close/reopen as well as app quit.

Persist enough timer state to preserve accumulated pauses, always restart the runner on resumed active timing, and cap credited running time at the configured timer budget. Do not award unattended sleep/closed-app time as known focus: present the recovered interval for review, with an honest uncertainty label. Do not discard an older-than-six-hours snapshot automatically without offering recovery (`index.html:4282–4285`).

**3. Save failures can lose completed work while reporting success.** `saveState()` catches a write failure with “Could not save settings locally.” `endSession()` then clears the active snapshot and offers completion feedback regardless (`index.html:1923–1925,3183–3203`). Active writes silently fail. Unsubmitted prompt text and choices are not serialized; restoring a prompt rebuilds empty fields (`index.html:4248–4301`). Crash/reload can also leave both the archived session and an uncleared active snapshot; archive by session ID to prevent duplicate finalization. Make durable-save success observable, retain recovery data until it succeeds, and offer retry/export on failure. Persist drafts if claiming prompt recovery. Until then, narrow the README promise.

**4. “Best window” does not measure effectiveness.** `computeBestHour()` counts local start hours among completed-flag cycles, requires only three total cycles, and resolves ties in favor of the earliest hour (`index.html:3506–3513`). There is no outcome comparison, competing-hour denominator, or adjustment for schedule availability. The subtitle “Most cycles started” does not repair the headline. Remove this card for MVP. A descriptive start-time chart can live in Details without any recommendation to schedule harder work at that hour.

**5. Today, seven days, and timeline disagree.** Setup goal compares the session's UTC start date with a local date key; history uses the cycle's local end date (`index.html:2480–2485,3244–3249,4194–4196`). The seven-day statistic uses a rolling 168 hours while bars show seven local calendar dates. Timeline uses fixed 24-hour day boundaries and elapsed hours since midnight; DST days are not always 24 hours. It clamps pre-6am work onto 6am, includes paused wall-clock time, and clips cross-midnight intervals (`index.html:3263–3269,3320–3344`).

Use a single policy throughout: current device timezone, explicit displayed timezone name, calendar boundaries built with date arithmetic, today plus six preceding dates for “Last 7 days.” For the MVP, attribute each ended cycle's recorded minutes to its local end date and disclose that rule. Do not fabricate per-day pause-adjusted segments from legacy timestamps. Show a 24-hour start-event list instead of a duration timeline until accurate intervals exist. Store timezone/offset for future records if original-location reporting is later wanted; historical epoch timestamps do not retain the user's original timezone. Travel can regroup old dates under the chosen current-zone policy. Refresh open totals at local midnight.

## Metric audit beyond the blockers

- **Target hit rate:** the existing denominator is explicitly displayed as reviewed cycles, a useful foundation. But it includes only completed-flag cycles, accepts any truthy outcome, needs just one response, excludes missing responses without showing coverage, and does not require a recorded target (`index.html:3357–3375`). The session row uses a different population: all reviewed cycles (`index.html:3424`). Use one shared predicate, strict outcome enum, period, and denominator everywhere. Partial must remain separate; do not assign it an invented half-success value.
- **Energy/morale:** full planning defaults both to 7; pressing Start saves those untouched defaults (`index.html:2730–2754`). Existing 7s cannot be distinguished from intentional 7s. Missing ratings then become zero in the chart (`index.html:3294–3315`), despite zero being outside the scale. Suppress aggregate claims for legacy ratings; retain them in detail with provenance caveats. New ratings must start unselected. Percentage bar heights inside an auto-height column also warrant visual verification; no rendering defect was visually confirmed here.
- **Distraction patterns:** this is a deduplicated list of planned, flagged, and actual text, capped at six. It does not calculate recurrence; deduplication removes the very counts needed to claim repetition (`index.html:3396–3417`). Planned hazards are predictions, not observed interruptions. Blank text means unreported, not distraction-free.
- **What to repeat:** verbatim `debrief.went_well` is valuable personal evidence, but no effectiveness test has occurred (`index.html:3380–3393`). Keep it as “Your notes on what worked” in session details, not another analytical card.
- **Retention/export:** load silently retains only the last 500 sessions, while in-process saves do not enforce that cap. “Everything you've logged” is therefore unsafe (`index.html:1911–1915,3187`). CSV omits session prep/debrief, including the notes behind What to repeat, and has no import/restore flow (`index.html:3529–3547`). Call it cycle CSV export, not a complete backup, unless coverage and restore are implemented. Provide explicit retention information and no silent pruning. Exercise quoted text, carriage returns, and spreadsheet-formula-leading user text in export acceptance tests.
- **Privacy voice:** README “Nothing is transmitted anywhere” is broader than the optional weather and online image code (`README.md:95–96`; `index.html:1976,2311–2352`). Use “Session content stays on this Mac,” alongside clear optional service disclosure. The Electron first-run handler hides the newly relevant weather/privacy line because it still treats it as an install hint (`index.html:1570,4167–4173`). This is a source mismatch, not a legal-policy review.

## Exactly three proposed actionable insights

Implement with existing local fields, ordinary JavaScript, and the existing UI. No AI, cloud, dependencies, text classification, or invented productivity score. Show the user's underlying record via a keyboard-operable link. Thresholds below are conservative product display rules, not statistical significance or causal evidence.

**Shared eligibility:** evaluate against one captured `now`. Use the current device timezone and the interval from local midnight 27 dates before today through `now`, inclusive. Use valid archived sessions with nonempty string IDs and cycles with integer indices; count each `(session.id, cycle.index)` once. If duplicate records conflict, exclude the conflicting key and disclose it rather than choosing silently. An ended cycle requires finite positive timestamps, `startedAt <= endedAt <= now`, with `endedAt` in this window. Ignore unstarted/planned-only cycles and the active unfinished cycle. Reject malformed records safely; show the number excluded. No claim is “all time” because retention is limited. Raw local data must remain unchanged.

### 1. Pick up your next action (P1, ship first)

- Source: `cycle.review.next_action`, written by both sprint and full review (`index.html:2660–2665,2805–2810`). Current `priorNextAction()` only carries within the same session (`index.html:2822–2825`).
- Rule: at least one eligible ended cycle with a nonempty trimmed string `review.next_action`. Choose the most recent `endedAt`, then stable session ID and cycle index for ties. Do not substitute `improvements`: that legacy field may be advice rather than an action. Do not infer that the action remains undone or relevant.
- Exact card: **“Last saved next action”**, the verbatim text, local date, and **“Use for next cycle”**. Supporting line: “You saved this after a cycle. Still the next step?” The button prefills an editable first-action field and never starts a timer or overwrites existing input without a choice.
- Empty: **“No next action saved in the last 28 days. You can leave one at the end of a cycle.”** Keep it small, with no warning badge. An older note stays available in history.
- Acceptance: zero/whitespace/malformed/future actions are excluded; latest dated note wins regardless of array order; HTML displays as text; interrupted cycles with a saved note are eligible; existing draft survives choosing a suggestion.

### 2. How your targets turned out (P1)

- Source: `plan.accomplish` and explicit `review.completed_target` (`index.html:2749,2806`). This describes self-report, not verified output.
- Rule: let **A** be all eligible ended cycles; **T** those with a nonempty trimmed string target; **R** those in T with exact outcome `yes`, `partial`, or `no`. Include ended-early/incomplete cycles if they have an explicit response. Do not filter by `completed`. Let Y/P/N be outcome counts. Show the distribution only when `R >= 5`, R covers at least three distinct local end dates, and `R / T >= 0.5`.
- Exact card: **“Targets you reviewed · last 28 days”**; **“Y yes · P partial · N no”**; **“Reviewed R of T recorded targets; U unanswered. A−T cycles had no recorded target.”** If displaying a percentage, it is only `round(100 * Y / R)` and labeled “Reported yes among reviewed targets.” Invalid responses count as unanswered, never No.
- Action: if `P + N > 0`, **“Review one partial or missed target”** opens the latest such record; supporting copy: “Would a smaller next target help?” This is an invitation, not a diagnosis. Otherwise **“Review a target you completed”** opens the latest Yes and asks “What would you repeat?”
- Empty when T=0: **“No recorded targets in the last 28 days. A target is optional.”** Otherwise, if any display rule fails: **“R of T targets reviewed across D days. More optional check-ins are needed for a summary.”** State the rule underneath: “At least 5 reviews on 3 days, covering half of recorded targets.” Do not show 0% when responses are missing.
- Acceptance: test exact threshold boundaries, all missing, all No, all Yes, partial-only, mixed target/no-target records, low coverage, skipped prompts, invalid enums, and interrupted cycles. Adding target-bearing cycles with missing reviews cannot improve or reduce the Yes percentage; it changes coverage only. Submitting an explicit new response can change that percentage.

### 3. A blocker entry you repeated (P2)

- Source: `cycle.review.distractions` only (`index.html:2808`). Never combine it with prep or plan hazards. Sprint mode currently does not collect this field; say so in the empty state.
- Rule: group eligible ended cycles by whole-field text after trim, whitespace collapse, and lowercase. Do not split lists, stem words, group synonyms, or interpret sentiment. Exclude exact normalized entries `none`, `no`, `n/a`, `na`, `nothing`, `no distractions`, and `no blockers`. Let B be cycles with remaining nonempty entries. Show only if `B >= 3` and a group appears in at least two cycles on at least two distinct local dates. Count one entry per cycle. Pick highest count, then latest occurrence, then lexical key for ties. Show only one group.
- Exact card: **“You wrote this more than once”**, newest verbatim spelling, and **“K of B cycles with blocker notes; D dates in the last 28 days.”** Also show **“B of A ended cycles included a blocker entry.”** Say “Exact text matches only; these are your notes.” Unknown blanks never become a denominator for a claimed distraction rate. A compound phrase is a repeated entry, not several classified blockers.
- Action: **“Review before the next cycle”** opens the matching notes and offers the quote as an editable planning hazard: “Anything to change before you begin?” Never assert the cause or auto-apply a remedy.
- Empty if B=0: **“No blocker notes in the last 28 days. Structured cycle reviews have an optional ‘What blocked you?’ field.”** Otherwise: **“No repeated blocker entry across separate days yet. Your notes are still available in history.”** Do not claim “No distractions.”
- Acceptance: same-day duplicates cannot qualify; planned hazards never count; blank/explicit-none entries never qualify; case and whitespace variants match; synonyms and negated sentences remain separate literal entries. Never present exact matching as complete detection of recurring distractions.

## Keyboard, reduced motion, and accessibility (P1 release gate)

Preserve the existing focus-visible ring, native buttons, labeled full-mode text fields, changing Pause/Resume accessible name, and reduced-motion guards (`index.html:266,2525,2943,805,4109`). Close these source-visible gaps:

- Global Space intercepts focused buttons: it may start the flow, pause, or suppress activation instead of activating that button. Modifier keys and key repeat are not guarded (`index.html:4389–4424`). Scope shortcuts away from interactive controls, contenteditable, modal/popover interaction, and Command/Control/Alt combinations. Standard button Space/Enter must work; held S must not skip multiple phases.
- Help dismisses on any key, including Tab, has no focus management or explicit close button, and does not mark the background inert. `role=menu` popovers have no arrow navigation or selected-state semantics (`index.html:1776,1803,3684–3691`). Use simple native disclosure controls where possible; implement a proper modal only for Help. Restore focus to the trigger and let Escape close the innermost surface first.
- Session rows and the mini expand hint are clickable divs without keyboard activation (`index.html:1771,3431–3455`). Make them native disclosure buttons with expanded state. At widths <=440px, setup/history/prompts are hidden; browser expansion is a no-op because there is no bridge (`index.html:1461–1477,3117–3123`). Preserve a usable narrow browser layout, and make native expansion keyboard-accessible. Mini-to-review must reveal the review without trapping the user.
- Associate labels for custom count, durations, daily goal, and daily intent. Sprint's empty label needs the heading associated with its textarea (`index.html:1586,1621–1643,1808,2600–2602`). Use native radios/fieldsets for choices and scales, with no preselected self-reports. Expose selected presets and preferences programmatically. Reveal quote navigation on focus as well as hover.
- Add a polite status region for saved/failed/phase-transition messages, not a per-second countdown announcement. Provide text values and date labels for charts; title tooltips and color alone are insufficient. Verify contrast over both themes and the lightest/darkest supported backgrounds; no contrast ratios were measured here.
- Reduced motion currently leaves hover movement and several transitions active; the break label becomes a permanent “Breathe in” (`index.html:851–854,1509–1519`). Use neutral static “Take a break,” suppress spatial flourishes, and respect preference changes during a session. Native resize animations also need consideration (`main.js:22,33`).

## Acceptance and release order

**P0 blockers before an MVP can claim trustworthy insights:** distinguish timer state from outcome; repair paused recovery and duration inflation; preserve data on failed saves and stale recovery; remove “Best window” effectiveness framing; unify date boundaries; stop manufacturing self-report through rating defaults. Either implement full backup/draft recovery or remove the unsupported promises. No historical data rewrite can reconstruct missing evidence.

**P1 release gates:** one-activation basic start, optional reviews with no rest gate, calm active mode, keyboard-safe controls and narrow layouts, inspectable insight denominators, and readable empty states. P2 recurrence insight and whimsy can wait; neither should delay correctness.

Add focused behavioral tests using the existing Node `assert`/`vm` approach or built-in test runner without dependencies; keep marker tests only as smoke checks. Test:

1. Expiry, early Skip, Stop, paused Skip/Stop, multiple pauses, quit/reload paused then Resume, late wake, >6h recovery, prompt drafts, and exactly-once archival. Use a controlled clock. Interrupted time survives independently of target outcome. No path awards more time than its trustworthy timer budget.
2. Storage write failure during finalization retains a recoverable record and does not announce Saved; retry does not duplicate. Malformed cycle/session data cannot crash startup, history, or export. Retention does not silently remove records.
3. Local/UTC date disagreement, midnight session crossing, spring/fall DST transitions, timezone change, and the same seven dates across goal/stat/bars. Run timezone fixtures explicitly, including America/Chicago and UTC. No pre-6am event is drawn at 6am; no missing interval is invented.
4. All eligibility boundaries for the three insight types, missing self-reports, duplicate/conflicting IDs, invalid timestamps/enums, and absence of any effect on results from the `completed` flag alone.
5. History opened during active work or a prompt, then a phase change while history is open. Returning must reveal the current flow, never a dead timer (`index.html:3576–3605` currently remembers a screen ID). Preserve drafts on ordinary history navigation.
6. CSV export in browser and native bridge: success, cancel, write failure, quotes/newlines/carriage returns/formula-leading text, and honest coverage of included fields. Native handler boundaries and size/name validation should be exercised (`main.js:95–117`; `preload.js:11`).

Then manually verify, in a disposable local profile: keyboard-only start/review/history/mini/Help, standard Space and modifier behavior, VoiceOver labels/status, reduced motion, 200% text zoom, light/dark/photo contrast, narrow browser view and native 420×88 bar, minimized/background notifications, and native close/reopen. These checks remain outstanding; the passing smoke test is not their substitute.
