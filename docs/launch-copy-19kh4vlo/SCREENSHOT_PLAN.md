# Screenshot plan — recommended direction

Status: storyboard and capture brief for discussion. No new marketing compositions are produced or approved yet. Existing `docs/store-assets-navigation/` files are raw reference captures, not the proposed final marketing set.

## One story, five screenshots

### 1. Home — “A timer with a plan.”
Supporting line: Choose your target, your cycles, and your next step.
Show: the real Home screen with Home selected, a filled daily intent, a modest cycle count and Start focusing. Keep the scenery visible.
Sample intent: “Draft the opening of the article.”
Use three cycles with consistent focus/break durations throughout the example. Avoid the current late-night, five-cycle example as the lead image.
Job: identify the product and its difference immediately.

### 2. Plan — “Know where to start.”
Supporting line: Name the task. Make the first move smaller.
Show: the actual planning fields, filled briefly enough to read.
Target: “Draft the opening paragraph.”
First action: “Open the document and write the first sentence.”
Possible distraction: “Checking messages before the draft is done.”
Job: prove that planning means a concrete action, not another task-management system.

### 3. Focus — “One target. One work session.”
Supporting line: Keep the next action beside the countdown.
Show: the same target, a partially elapsed timer, horizontal progress, and visible pause/Compact controls. Use dark mode here so it earns a place in the story rather than requiring a duplicate Home image.
Job: make the countdown readable at thumbnail size and show how the target stays present.
Use a controlled, isolated sample session for the time state. Do not imply that fictional elapsed time is a real user's productive result.

### 4. Review — “Take a useful note forward.”
Supporting line: Record what happened and what to try next.
Show: actual review inputs, filled with an honest, mixed result.
Sample reflection: “The opening is drafted. It still needs a sharper example.”
Next action: “Find one example, then revise the first paragraph.”
Map sample text only to fields that actually exist. A skipped timer is not a successful cycle. Do not add a success badge or fabricate a perfect score.
Job: show why this is more than a countdown. Use the app's own saved-history affordance if visible; do not invent a combined review/history screen.

### 5. Compact — “Keep the timer nearby.”
Supporting line: Compact mode and a Mac menu bar countdown.
Show: the real compact window at a readable scale. Prefer a controlled sample workspace; never capture Bud's private desktop. If the menu bar is shown, use an actual native capture from the same sample session.
Job: demonstrate the Mac-specific convenience. Keep window controls true to the real app, with no fake Apple app chrome.

## Visual treatment
- Recommended: a real, large app capture with one short caption above it. An understated frame, not a fake laptop floating in space.
- Alternative considered: raw edge-to-edge captures. These maximize UI size but tell less of the planning/review story. Use them as the fallback if a caption band makes the actual controls too small.
- One scenic family across the set. Show dark mode in the Focus frame; do not cycle through unrelated wallpapers.
- Use the existing icon and identity. No new logo, oversized arrows, decorative charts, ratings or testimonial badges.
- Keep the first screenshot's caption readable at thumbnail size. Enlarge the relevant view through native capture sizing rather than inventing controls or retouching labels.
- Preserve keyboard focus styling only when intentional; remove accidental cursor/hover states before capture.
- Use a daytime example with consistent dates, cycle counts, durations and task text. Change only an isolated QA clock/profile, never system time or real user records.
- Quotes are supporting texture, not the main promise. Preserve their source wording and attribution if visible.

## File specification and checks
Produce 2880×1800 RGB PNGs without alpha, captured at genuine Retina resolution rather than enlarging the existing 1440×900 files. Apple also accepts 1440×900 if that yields the clearest practical set. Keep all five consistent at 16:10.

Check every export: dimensions, RGB/no alpha, source/candidate identity, complete controls, readable captions, clean state, and no private data. Review at both full size and Store thumbnail scale.

Apple allows one to ten Mac screenshots. Five is our recommendation, not an Apple requirement. Video is optional and is not needed for this release. Do not delay submission to make an app preview video.

## What needs approval
Approve or revise the positioning and the five-shot story before designing the final compositions. Current raw captures remain available as a fallback. This is a marketing presentation change, not a request to add product features.
